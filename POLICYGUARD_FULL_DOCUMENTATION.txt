1. PROJECT OVERVIEW
====================================================================================================

PolicyGuard is a production-ready, enterprise-grade Web Security Header & Cookie Scanner built on the 
MERN stack. It conducts non-intrusive automated security audits of public websites by sending HTTP/HTTPS 
GET requests, inspecting response headers, tracking HTTP redirect chains, parsing Set-Cookie flags, 
and evaluating compliance against modern web security standards (OWASP, NIST, ChatGPT 100-Point Weighted 
Security Benchmark).

KEY CAPABILITIES:
- 100-Point Weighted Scoring Algorithm & Letter Grade System (A+ to F).
- SSRF (Server-Side Request Forgery) Defense: Validates input URLs and blocks loopback/private/internal 
  IP ranges (127.0.0.1, 10.x.x.x, 192.168.x.x, 172.16-31.x.x, CGNAT, Link-Local) via DNS resolution and ipaddr.js.
- Strict Security Header Auditing: Evaluates HSTS, CSP, X-Content-Type-Options, X-Frame-Options, 
  Referrer-Policy, Permissions-Policy, and COOP (Cross-Origin-Opener-Policy).
- Cookie Security Audit: Parses Set-Cookie headers, checking HttpOnly, Secure, SameSite flags, and 
  __Secure- / __Host- prefix directives while redacting sensitive session values.
- HTTP Redirect Chain Tracking: Follows up to 5 HTTP redirects (301, 302, 303, 307, 308) to inspect 
  header configurations across redirect paths.
- Remediation Code Generation: Instant copy-paste remediation snippets for Nginx configuration and Node.js/Express (Helmet middleware).
- AI Enrichment Integration: Integrates with OpenAI API (gpt-4o-mini) to provide plain-English executive 
  summaries, CSP vulnerability analysis, and customized remediation plans.
- High-Availability Fallback: Gracefully operates in memory if MongoDB is disconnected or unavailable.
- Export Capabilities: One-click export of full audit reports in formatted JSON structure.

4. HOW IT WORKS - CORE DATA & EXECUTION WORKFLOW
====================================================================================================

STEP 1: USER INPUT & SUBMISSION
  User enters a domain or URL (e.g. `github.com` or `https://example.com`) in `ScanForm.jsx`.
  The input is validated client-side and sent via HTTP POST to `http://localhost:5000/api/scan`.

STEP 2: RATE LIMITING & ROUTING
  `rateLimiter.js` checks the client IP address. If within 30 requests/15 mins, request reaches 
  `scanController.createScan`.

STEP 3: URL NORMALIZATION & SSRF PROTECTION (`scannerEngine.js`)
  a. Prepend `http://` if protocol is missing.
  b. Parse URL hostname.
  c. Reject obvious local hostnames (`localhost`, `127.0.0.1`, `::1`, `.local`, `.internal`).
  d. Perform DNS lookup via Node's `dns.promises.lookup` to retrieve IPv4 and IPv6 target addresses.
  e. Parse resolved IPs with `ipaddr.js`. If any address resolves to private, loopback, link-local, 
     or CGNAT ranges, execution immediately halts with an SSRF Protection Error.

STEP 4: HTTP SCANNING & REDIRECT CHAIN TRACKING (`scannerEngine.js`)
  a. Initiate network GET request using native `fetch` with `redirect: 'manual'` and custom Chrome User-Agent.
  b. Capture response status code, timing, and response headers.
  c. Sanitize headers: mask sensitive header values (`Authorization`, `Cookie`, `X-Api-Key`, session values) 
     with `*** REDACTED ***`.
  d. If response returns a 3xx redirect status (301, 302, 303, 307, 308) and `Location` header, 
     record the redirect step in `redirectHistory` array and follow up to 5 hops max.

STEP 5: HEADER & COOKIE ANALYSIS (`scoring.js`)
  a. `analyzeHeaders()`: Compares raw response headers against 7 security specifications:
     1. Strict-Transport-Security (HSTS) - [20 Max Points]
     2. Content-Security-Policy (CSP) - [20 Max Points]
     3. X-Content-Type-Options - [15 Max Points]
     4. X-Frame-Options - [15 Max Points]
     5. Referrer-Policy - [10 Max Points]
     6. Permissions-Policy - [10 Max Points]
     7. Cross-Origin-Opener-Policy (COOP) - [10 Max Points]
  b. `analyzeCookies()`: Parses `Set-Cookie` headers via `set-cookie-parser`. Evaluates flags:
     - HttpOnly flag presence
     - Secure flag presence
     - SameSite directive (Strict / Lax / None)
     - Prefix validation (__Secure- / __Host-)
     - Exposes flag status while redacting actual cookie values to `*** REDACTED ***`.
  c. `calculateScoreAndGrade()`: Computes total earned points against total max points (100-point scale) 
     and maps score to Letter Grades:
     - 95 to 100 -> Grade A+
     - 85 to 94  -> Grade A
     - 75 to 84  -> Grade B
     - 60 to 74  -> Grade C
     - 45 to 59  -> Grade D
     - 0  to 44  -> Grade F

STEP 6: AI ENRICHMENT (`aiService.js`)
  Optionally triggers OpenAI API request (`gpt-4o-mini`) to generate executive risk summary, CSP 
  vulnerability breakdown, and tailored remediation instructions. Returns safe fallback if API key is missing.

STEP 7: PERSISTENCE & RESPONSE
  Saves full scan result object to MongoDB database via Mongoose `Scan` model.
  If MongoDB is offline, stores in `inMemoryScans` buffer array (up to 20 recent scans).
  Returns JSON payload to React client UI for real-time rendering.

5. DETAILED MODULE BREAKDOWN & IMPLEMENTATION SPECIFICATIONS
====================================================================================================

----------------------------------------------------------------------------------------------------
SERVER MODULES
----------------------------------------------------------------------------------------------------

1. `server.js`
   - Express server entry point listening on PORT (Default: 5000).
   - Configures CORS origin matching `CLIENT_URL` (http://localhost:5173).
   - Mounts Express JSON parser and URL-encoded middleware.
   - Registers `/api` scanner routes.
   - Exposes Health Check endpoint: GET `/api/health`.
   - Contains global 404 handler and 500 error handling middleware.

2. `config/db.js`
   - Connects to MongoDB database specified by `MONGO_URI`.
   - Uses `serverSelectionTimeoutMS: 3000` to prevent hanging connection attempts.
   - Sets global flag `isConnected`. If connection fails, logs warning and enables in-memory fallback.

3. `models/Scan.js`
   - Mongoose Schema defining scan document fields:
     - `targetUrl`: String
     - `domain`: String
     - `score`: Number
     - `grade`: String
     - `redirectHistory`: Array
     - `headerResults`: Array
     - `cookieResults`: Array
     - `rawHeaders`: Object
     - `scanDurationMs`: Number
     - `aiEnrichment`: Object
     - `scannedAt`: Date

4. `routes/scanRoutes.js`
   - POST   `/api/scan`     -> `createScan` (Protected by scanRateLimiter)
   - GET    `/api/history`  -> `getScanHistory` (Returns 10 most recent scans)
   - GET    `/api/compare`  -> `compareScans` (Compares domainA vs domainB)
   - GET    `/api/scan/:id` -> `getScanById` (Retrieves full scan details)
   - DELETE `/api/history`  -> `clearHistory` (Purges all stored scans)

5. `utils/scoring.js`
   - Defines `WELL_KNOWN_HSTS_PRELOADED_DOMAINS` list (google.com, github.com, etc.).
   - Contains `HEADER_SPECS` array with logic, points, risk messages, and Nginx/Express fix snippets.
   - Handles HSTS evaluation logic: checks max-age >= 31536000 (1 year), includeSubDomains, and preload lists.
   - Handles CSP directive parsing: checks for `'unsafe-inline'`, `'unsafe-eval'`, wildcard `*`, nonces, and hashes.
   - Calculates score percentage mapped to 100 points.

6. `utils/scannerEngine.js`
   - Implements `isPrivateIp()` using `ipaddr.js` range checking.
   - Implements `normalizeAndValidateUrl()` to enforce URL safety and prevent SSRF attacks.
   - Implements `scanTarget()` executing HTTP request, measuring latency, tracking redirect hops, 
     parsing raw headers & cookies, and returning final structured scan object.

----------------------------------------------------------------------------------------------------

1. `App.jsx`
   - Main dashboard component managing application navigation tabs (`Live Scanner` vs `Headers Guide`).
   - Handles JSON report download execution.
   - Integrates `ScoreGauge`, `SecurityFindings`, `HeaderAccordion`, `RedirectChain`, `Recommendations`, 
     `CookieTable`, `ScanHistory`, and `KnowledgeBase`.

2. `hooks/useScan.js`
   - Custom hook managing scan state (`scanResult`, `history`, `loading`, `error`).
   - Encapsulates async backend API calls (`executeScan`, `selectScan`, `clearScanHistory`, `fetchHistory`).

3. `components/ScoreGauge.jsx`
   - Visual score presentation using an animated SVG circular progress gauge.
   - Displays color-coded Grade Badge (Green for A+/A, Emerald for B, Amber for C, Orange for D, Red for F).
   - Displays scan metadata: target domain, final URL, scanned timestamp, latency duration, and raw header button.

4. `components/HeaderAccordion.jsx`
   - Collapsible list view for each of the 7 evaluated security headers.
   - Visual status badges (`PASS`, `WARN`, `MISSING`).
   - Expandable detailed breakdown containing Header Description, Risk Statement, Recommendation, 
     and Nginx / Express `CodeFixCard.jsx` code snippets.

5. `components/CookieTable.jsx`
   - Responsive data table listing scanned cookies.
   - Displays Cookie Name, Value (`*** REDACTED ***`), Path, SameSite attribute, HttpOnly status, 
     Secure status, and Risk Level (`SECURE`, `MEDIUM`, `HIGH`).

6. `components/Recommendations.jsx`
   - Action priority panel listing recommended fixes sorted by security impact score.
   - Helps site administrators focus on fixing high-severity vulnerabilities first.

7. `components/RedirectChain.jsx`
   - Visual timeline displaying step-by-step HTTP redirect paths (e.g. `http://domain.com` -> `https://domain.com` -> `https://www.domain.com`).
   - Displays status code for each hop (301, 302, 200 OK) and response latency.

8. `components/KnowledgeBase.jsx`
   - Comprehensive interactive security header documentation hub for developers.
   - Explains standard header syntax, common security risks, and best practices.

6. SECURITY EVALUATION MATRIX & SCORING BENCHMARK
====================================================================================================

HEADER NAME                      MAX PTS   CRITERIA FOR MAX POINTS (PASS)
----------------------------------------------------------------------------------------------------
Strict-Transport-Security (HSTS)  20 pts   HTTPS enabled AND (max-age >= 31536000 & includeSubDomains) 
                                           OR domain is present in HSTS Preload list.
Content-Security-Policy (CSP)     20 pts   Enforced CSP present without 'unsafe-inline' or '*'.
X-Content-Type-Options           15 pts   Value set strictly to "nosniff".
X-Frame-Options                  15 pts   Value set to "DENY" or "SAMEORIGIN" (or CSP frame-ancestors).
Referrer-Policy                  10 pts   Set to "strict-origin-when-cross-origin", "same-origin", 
                                           "no-referrer", or "strict-origin".
Permissions-Policy               10 pts   Restricts camera=(), microphone=(), geolocation=().
Cross-Origin-Opener-Policy (COOP) 10 pts   Set to "same-origin".
----------------------------------------------------------------------------------------------------
TOTAL MAXIMUM POINTS             100 pts


LETTER GRADE THRESHOLDS:
- Grade A+ : 95 - 100 Points (Exceptional header security posture)
- Grade A  : 85 - 94 Points  (Strong overall security)
- Grade B  : 75 - 84 Points  (Good posture, minor improvements recommended)
- Grade C  : 60 - 74 Points  (Moderate security gaps present)
- Grade D  : 45 - 59 Points  (Significant security headers missing)
- Grade F  : 0  - 44 Points  (Critical security vulnerability / unencrypted HTTP)

7. INSTALLATION & OPERATIONAL GUIDE
====================================================================================================

PREREQUISITES:
- Node.js (v18.0.0 or higher) installed.
- npm (v9.0.0 or higher) installed.
- (Optional) Local MongoDB server running on port 27017 (or MongoDB Atlas URI).

SETUP INSTRUCTIONS:

1. Clone Repository & Install Dependencies:
   $ npm run install:all
   (This executes `npm install` in both `server/` and `client/` directories).

2. Configure Environment Variables:
   Create a `.env` file inside `server/` folder with the following key-value pairs:
   --------------------------------------------------
   PORT=5000
   MONGO_URI=mongodb://127.0.0.1:27017/policyguard_scanner
   NODE_ENV=development
   CLIENT_URL=http://localhost:5173
   OPENAI_API_KEY=your_optional_openai_api_key_here
   --------------------------------------------------

3. Running the Project:
   
   Option A: Start Backend Server Only
   $ npm run dev:server
   (Runs on http://localhost:5000)

   Option B: Start Frontend Client Only
   $ npm run dev:client
   (Runs on http://localhost:5173)

   Option C: Run Both Server & Client concurrently
   In Terminal 1: cd server && npm run dev
   In Terminal 2: cd client && npm run dev

4. Accessing Application:
   Open browser and navigate to: http://localhost:5173

8. REST API SPECIFICATION SUMMARY
====================================================================================================

1. Health Check
   - Endpoint : GET /api/health
   - Response : { "status": "online", "timestamp": "...", "service": "PolicyGuard Engine" }

2. Execute Security Scan
   - Endpoint : POST /api/scan
   - Body     : { "url": "https://example.com" }
   - Rate Limit: 30 requests / 15 minutes per IP
   - Response : { "success": true, "data": { ...scanResults } }

3. Retrieve Scan History
   - Endpoint : GET /api/history
   - Response : { "success": true, "count": 10, "data": [ ...recentScans ] }

4. Fetch Scan Detail by ID
   - Endpoint : GET /api/scan/:id
   - Response : { "success": true, "data": { ...scanResult } }

5. Compare Two Domains
   - Endpoint : GET /api/compare?domainA=github.com&domainB=google.com
   - Response : { "success": true, "data": { "scanA": { ... }, "scanB": { ... } } }

6. Clear Scan History
   - Endpoint : DELETE /api/history
   - Response : { "success": true, "message": "Scan history cleared successfully." }
